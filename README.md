# Dusktale

(ชื่อเดิม NovelTranslate AI) เว็บแอพอ่านนิยายจีน ญี่ปุ่น เกาหลี อังกฤษ แปลไทยด้วย AI ทำงานในเบราว์เซอร์ล้วนๆ ไม่มี backend และไม่ต้อง build
ข้อมูลนิยาย ตอน และคลังศัพท์ทั้งหมดเก็บใน IndexedDB ของเบราว์เซอร์เครื่องนั้น

## ความสามารถหลัก

- **วางลิงก์แล้วแปล**: ดึงเนื้อหาผ่าน `r.jina.ai` รองรับบทที่แบ่งหลายหน้า หาลิงก์ตอนถัดไปได้หลายภาษา (下一章 / 次へ / 다음화 / Next Chapter / ตอนต่อไป) และ `rel="next"`
- **หลายภาษาต้นฉบับ**: จีน ญี่ปุ่น เกาหลี อังกฤษ (ตรวจอัตโนมัติ แก้เองได้ต่อเรื่อง) prompt กฎตรวจ และคลังศัพท์ปรับตามภาษา
- **เว็บต้นฉบับ**: โปรไฟล์เว็บ (CSS selector / ให้ r.jina.ai อ่านเฉพาะบางส่วน / เพิ่มเลขตอนใน URL) พร้อมเครื่องมือทดสอบ, นำเข้า/ส่งออกโปรไฟล์, เตือนเมื่อโปรไฟล์หาเนื้อหาไม่เจอติดกัน, Jina API key, proxy สำรองของตัวเอง (เช่น Cloudflare Worker), ให้ AI ช่วยแยกเนื้อหาเมื่อเว็บดึงยาก, โหมดสารบัญ (หาตอนถัดไปแม่นยำ เรียงตอน เติมตอนที่ขาด)
- **เช็กตอนใหม่**: ต่อเรื่องหรือทุกเรื่อง (จากสารบัญ หรือลิงก์ตอนถัดไปของตอนล่าสุด) แล้วเพิ่มเป็นตอนที่รอแปล ไม่ใช้โควตา AI
- **โปรไฟล์ตั้งต้น**: syosetu, kakuyomu, royalroad, webnovel.com, wtr-lab.com
- **วางข้อความ / ไฟล์ .txt .epub**: แยกตอนอัตโนมัติ เดา encoding ไฟล์จีน (GBK/Big5) และเข้าคิว "รอแปล"
- **เลือก AI ได้ 3 แบบ**: Google Gemini, Anthropic Claude, OpenAI / OpenAI-compatible (OpenRouter, DeepSeek, LM Studio ฯลฯ) ใส่ได้หลายคีย์ และหมุนคีย์อัตโนมัติเมื่อโควต้าเต็ม
- **คลังศัพท์อัจฉริยะ**: สกัดชื่อเฉพาะอัตโนมัติ, ล็อกคำแปล, ไฮไลต์ในเนื้อเรื่อง, แยกหมวด 7 หมวด, ใช้ร่วมทุกเรื่องหรือเฉพาะเรื่อง และตั้ง **คำแปลเฉพาะเรื่อง** ได้ (คำจีนเดียวกันแต่ละเรื่องแปลต่างกัน)
- **อ่านต่อเนื่อง**: infinite scroll (บนหน้ามีไม่เกิน 4 ตอน อ่านยาวแค่ไหนก็ไม่หน่วง เลื่อนขึ้นได้ ตำแหน่งไม่กระโดด), แปลบทถัดไปล่วงหน้า, แปลล่วงหน้าหลายบท (batch), จำตำแหน่งอ่านถึงระดับย่อหน้า
- **ตั้งค่าการอ่าน (Aa)**: ธีม ขนาด ฟอนต์ (Sarabun / Noto Sans Thai / Noto Serif Thai / Kanit / ฟอนต์เครื่อง) ระยะบรรทัด ระยะห่างย่อหน้า ความกว้างหน้า โหมดต่อเนื่อง/ทีละตอน และปุ่มเลื่อนทีละหน้าจอ (▲▼ / ลูกศรซ้ายขวา) ไม่เปลี่ยนการจัดย่อหน้า
- **ฟังเสียงอ่าน (🎧)**: Web Speech API อ่านทีละย่อหน้า ไฮไลต์ย่อหน้าที่อ่าน ปรับความเร็ว/เสียง อ่านต่อตอนถัดไป (รอแปลล่วงหน้าได้) กันจอดับระหว่างฟัง และบอกวิธีติดตั้งเสียงไทยถ้าเครื่องไม่มี
- **เพลงประกอบ (🎵)**: ตอนฟังเสียงอ่าน (หรืออ่านเงียบถ้าเปิดไว้) เล่นเพลงเบาๆ ตามอารมณ์ของฉาก 9 แบบ แยกตามแนวเรื่อง เฟดข้ามเมื่อเปลี่ยนอารมณ์ (ไม่ถี่กว่า 20 วินาที) อารมณ์มาจาก AI ตอนทำบันทึกเหตุการณ์ (แก้ได้ในแท็บ 📜) ถ้าไม่มีจะเดาจากคำ ไฟล์อยู่ที่ `audio/bgm/<แนว>/<อารมณ์>.mp3` รายการและพรอมต์สร้างเพลงอยู่ใน `docs/bgm-prompts.md`
- **ประวัติเวอร์ชันของตอน (🕘)**: แปลใหม่ / วางเนื้อหาเต็ม / ดึงใหม่ / ใช้ผลเทียบโมเดล แล้วเก็บคำแปลเดิมไว้ (ค่าเริ่มต้น 3 ฉบับต่อตอน, store `chapterVersions`) เทียบทีละย่อหน้า กู้คืนทั้งตอนหรือทีละย่อหน้า อยู่ในไฟล์สำรอง
- **รายงานคุณภาพทั้งเรื่อง (📋)**: ย่อหน้าน่าสงสัย, ตรวจความหมายหลังเกลาไม่ผ่าน, ตอนที่แปลด้วยคำสั่งรุ่นเก่า, ตัวละครรอยืนยัน, คำศัพท์ที่ AI เพิ่มเองยังไม่ยืนยัน, ตอนที่ยังไม่แปล/ต้องซื้อ/แปลจากตัวอย่าง กดไปที่ย่อหน้าได้ ไม่ใช้ AI
- **คลังศัพท์เป็นไฟล์**: ส่งออก CSV (มี BOM เปิดใน Excel ได้) / JSON ทั้งคลังหรือเฉพาะเรื่อง นำเข้า CSV/TSV/JSON พร้อมตัวอย่างก่อนนำเข้า และเลือกเองว่าคำที่ชนกันจะข้าม / แทนคำแปลหลัก / ใช้เฉพาะเรื่องนี้
- **เทียบโมเดล (🧪)**: แปลตอนเดียวกันด้วยโมเดลสูงสุด 4 ตัว เทียบคำแปลทีละย่อหน้า เวลา token จริง และราคาต่อตอน/ต่อ 1,000 ตอน (`setModelOverride` ผูกโมเดลกับ signal ของงาน ไม่แตะการตั้งค่าหลัก ไม่เขียนคลังศัพท์)
- **ค้นหาและบุ๊กมาร์ก (🔎)**: ค้นข้อความในคำแปล/ต้นฉบับ เรื่องเดียวหรือทุกเรื่อง (ไม่สนการเว้นวรรค) กดผลเพื่อไปที่ย่อหน้า บุ๊กมาร์กและโน้ตระดับย่อหน้า (หาย่อหน้าเจอแม้แปลใหม่แล้วย่อหน้าเลื่อน) อยู่ในไฟล์สำรอง
- **เลขตอนจริง**: อ่านเลขตอนจากชื่อตอน/หัวตอน/URL (`computeChapterNumbers`) ใช้ในผู้ช่วย AI บันทึกเหตุการณ์ ผลค้นหา และบุ๊กมาร์ก เริ่มอ่านในแอพจากตอน 801 ก็อ้างเป็น #801 ไม่ใช่ #1
- **หน้าแรก / ชั้นหนังสือ (📚)**: หน้าเต็มจอที่ลอยทับหน้าอ่าน (ตำแหน่งอ่านไม่หาย) การ์ดหนังสือมีปก (ใส่รูปเองได้ ย่อเป็น 360×540 JPEG เก็บใน `bookData.cover` หรือใช้ปกสีอัตโนมัติ) แถบว่าอ่านไปเท่าไร ป้ายตอนใหม่ ปุ่ม ▶ อ่านต่อ / ⚡ แปลล่วงหน้า / ⋯ และการ์ด "อ่านต่อ" ด้านบน ค้นหาและเรียงได้ หน้ารายละเอียดของเรื่องมีรายการตอนทั้งหมด (เลือกหลายตอนเพื่อย้าย/ลบ, ⋯ ของแต่ละตอน) ปุ่มย้อนกลับของมือถือใช้ได้ เลือกได้ว่าเปิดแอพแล้วไปหน้าแรกหรือตอนที่อ่านค้าง
- **แปลล่วงหน้าหลายเรื่อง**: กด ⚡ ได้หลายเรื่อง เรื่องที่กดทีหลังเข้าคิว แต่ละการ์ดมีแถบความคืบหน้า ปุ่มหยุด/ยกเลิกคิว และผลลัพธ์ (`batchQueue` / `batchCurrent` / `batchResults` ใน `js/shelf.js`)
- **เมนู ⋯**: ปุ่ม "⋯ ตอนนี้" ข้างชื่อตอน รวมคำสั่งของตอน (แปลใหม่ ถามก่อนเสมอ / สแกนคำศัพท์ / ประวัติคำแปล / รายงานคุณภาพ / ส่งออก .TXT) มือถือ: หัวจอเหลือ "+ วางลิงก์" กับ ⋯ (คลังศัพท์ คู่มือเรื่อง ตั้งค่า ติดตั้งแอพ) แถบล่างมี ชั้นหนังสือ Aa 🔎 🎧 ⛶ เต็มจอ เมนูใช้ลูกศร/Esc ได้ บนมือถือเป็นแผ่นเลื่อนจากล่าง
- **ตั้งค่าแบ่งหมวด**: 🤖 AI / 📝 การแปล / 📖 การอ่าน / 💾 ข้อมูล / 🧰 เครื่องมือ (จำหมวดล่าสุด ยังไม่มีคีย์เปิดหมวด AI ก่อน) คลังศัพท์บนมือถือเปิดเต็มจอ ฟอร์มเพิ่มคำซ่อนไว้จนกด "+ เพิ่มคำ" งานที่ใช้ไม่บ่อยอยู่ในเมนู ⋯
- **กล่องของแอพ**: แจ้ง/ยืนยัน/ถามข้อความด้วยกล่องของแอพแทน alert/confirm/prompt ของเบราว์เซอร์ (`js/dialogs.js`) ปุ่มบอกผลของการกด ปุ่มลบไม่ถูกโฟกัสให้เอง Esc = ยกเลิก
- **ส่งออก/สำรอง**: ส่งออกทั้งเรื่องเป็น TXT / EPUB, สำรองและนำเข้าข้อมูลทั้งหมดเป็น `.json` (ไม่รวม API Key)
- **PWA**: ติดตั้งเป็นแอพบนมือถือ/คอม และเปิดอ่านตอนที่บันทึกไว้ได้แม้ออฟไลน์
- **ผู้ช่วย AI (💬 มุมขวาล่าง)**: ถามเรื่องนิยายที่อ่าน (ตัวละครโผล่ตอนไหน ระดับพลัง ความสัมพันธ์ สรุปเรื่อง เทียบกับเรื่องอื่น) และวิธีใช้แอพ ตอบจากตอนที่แปลแล้วถึงตำแหน่งที่อ่าน (กันสปอยล์) พร้อมอ้างอิงตอน [#N] ใช้ "บันทึกเหตุการณ์" รายตอน (ระดับพลัง ของที่ได้/เสีย ความสัมพันธ์ ตัวตน ฉายา) คำนวณสถานะ ณ ตอนที่อ่าน กด 👎 เพื่อแก้ข้อมูลให้ผู้ช่วยจำ
- **ข้อมูลไม่หาย**: ขอพื้นที่จัดเก็บถาวร, เตือนเมื่อไม่ได้สำรองนาน, สำรองอัตโนมัติลงโฟลเดอร์ (Chrome/Edge บนคอม), นำเข้าไฟล์สำรองแบบรวมหรือแทนที่ทั้งหมด
- **ความปลอดภัย**: Content-Security-Policy จำกัดปลายทางที่ส่งข้อมูลได้, ตัวเลือกไม่จำ API Key หลังปิดแท็บ, ตรวจไฟล์สำรอง/ไฟล์นำเข้า, ล็อกงานแปลระหว่างหลายแท็บ
- **คุมค่าใช้จ่าย**: นับ token ที่ใช้จริงจากผู้ให้บริการ, แดชบอร์ดรายวัน/รายเดือน/รายเรื่อง, เพดานต่อวัน/ต่อเดือน (token หรือ USD), prompt caching, บันทึกข้อผิดพลาด (ตัด key ออก)

## โครงสร้างโค้ด

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` / `styles.css` | UI ทั้งหมด (modal ต่างๆ อยู่ในหน้าเดียว) |
| `js/csp.js` | สคริปต์แรกของหน้า: ตั้ง Content-Security-Policy (ปลายทางที่ส่งข้อมูลได้) |
| `js/dialogs.js` | กล่องแจ้ง/ยืนยัน/ถามของแอพ (`appAlert` / `appConfirm` / `appPrompt` / `appChoose`, เข้าคิวทีละกล่อง) และเมนู ⋯ (`openActionMenu`) |
| `js/db.js` | IndexedDB (`books`, `chapters`, `glossaries`, `bookData`, `meta`, `usage`, `chapterVersions`), แคชคลังศัพท์, สำรอง/นำเข้าข้อมูล (ตรวจทุกเรคคอร์ด) |
| `js/safety.js` | ที่เก็บ API Key, การตั้งค่าในไฟล์สำรอง, พื้นที่ถาวร, เตือน/สำรองอัตโนมัติ, จำกัดขนาดไฟล์นำเข้า, ล็อกระหว่างแท็บ (Web Locks) และแจ้งแท็บอื่น (BroadcastChannel) |
| `js/llm.js` | ชั้นเชื่อมต่อ AI: `callLLM()` / `callLLMJson()` รองรับ 3 provider, retry, หมุนคีย์, structured output (JSON schema), ยกเลิกงาน (`beginTask` / `abortTask`) |
| `js/usage.js` | นับ token จริง, ราคา/เงินโดยประมาณ, เพดานค่าใช้จ่าย, เพดานจำนวนครั้งต่อตอน, บันทึกข้อผิดพลาด |
| `js/lang.js` | ข้อมูลตามภาษาต้นฉบับ: ตรวจภาษา, คำแนะนำการแปล, ตัวอักษรที่ห้ามหลงเหลือ, เกณฑ์ความยาว |
| `js/api.js` | scraper (`scrapePage`), แยกประเภทเนื้อหา, prompt, pipeline แปล (`translateChapter`): แบ่งส่วน, ตรวจทาน, เกลา + ตรวจความหมาย |
| `js/source.js` | ตัวดึงหน้าเว็บ (r.jina.ai + proxy สำรอง), โปรไฟล์เว็บ + แยกเนื้อหาจาก HTML, AI ช่วยแยกเนื้อหา, สารบัญ, นำเข้าข้อความ/ไฟล์ (.txt/.epub) |
| `js/cleanup.js` | ทำความสะอาดคำแปลแบบไม่ใช้ AI (เครื่องหมาย, คำสะกดผิด, กฎแทนคำ) โดยไม่แตะคำในคลังศัพท์ |
| `js/bible.js` | คู่มือเรื่อง (ตัวละคร/สรรพนาม/แนวทางสำนวน), ตัวอย่างสำนวนจากที่ผู้ใช้แก้ |
| `js/glossary.js` | UI และ logic คลังศัพท์, คำแปลเฉพาะเรื่อง (override), ไฮไลต์คำ |
| `js/shelf.js` | ระบบแปลล่วงหน้า (คิวหลายเรื่อง + สถานะความคืบหน้า), รายการตอนของแต่ละเรื่อง |
| `js/home.js` | หน้าแรก/ชั้นหนังสือเต็มหน้า: การ์ดพร้อมปก หน้ารายละเอียดของเรื่อง ภาพปก ปุ่มย้อนกลับ (history) |
| `js/storylog.js` | บันทึกเหตุการณ์รายตอน (ชื่อเก็บตามต้นฉบับ ไม่กระทบเมื่อแก้ชื่อไทย), กลุ่มชื่อเดียวกัน, เส้นเวลา/สถานะ, สร้างย้อนหลัง, แท็บดู/แก้ในคู่มือเรื่อง |
| `js/assistant.js` | ผู้ช่วย AI: ค้นข้อมูลในเครื่อง (ชื่อ/คำค้น/สรุปรายตอน/สรุปช่วงเรื่อง), ข้อเท็จจริงที่คำนวณเอง, ตรวจการอ้างอิงตอน, คู่มือการใช้งานแอพ |
| `js/updates.js` | เช็กตอนใหม่ (สารบัญ / ลิงก์ตอนถัดไป) และเพิ่มเป็นตอนที่รอแปล |
| `js/quality.js` | ประวัติเวอร์ชันของตอน (เก็บ/เทียบ/กู้คืน) และรายงานคุณภาพทั้งเรื่อง |
| `js/glossary-io.js` | นำเข้า/ส่งออกคลังศัพท์ CSV/TSV/JSON (ตัวแยก CSV ตาม RFC 4180, จัดการคำที่ชนกัน) |

### หลักการสำคัญในโค้ด

- **สีและขนาดใช้ token/คลาสกลาง** (`styles.css` ส่วนบน): สีตัวอักษรเน้น `--accent-text`, สถานะ `--warning` `--success` `--danger` `--info` (+ `-soft` สำหรับพื้น) แต่ละธีมมีค่าของตัวเอง ห้ามใส่สีตรงๆ ใน HTML/JS เพราะธีมมืดจะอ่านไม่ออก คลาสกลาง: `.btn-sm` `.hint` `.modal-actions` `.mono` `.empty-note` `.text-*` `.status-*` (กล่องสถานะใช้ `setStatusTone(el, 'info' | 'warn' | 'error')`)
- **ย่อหน้าใช้คีย์บอร์ดได้**: `.para-th` เป็น role=button กด Enter/Space เปิดต้นฉบับ (`setupParagraphKeyboard`)

- **ฟังก์ชันแปลทุกตัวรับ `BookContext`** (`{ bookId, title, author, genre }`) เป็นพารามิเตอร์
  ห้ามอ่าน `currentBookId` / `currentBookGenre` ตรงๆ ในงานเบื้องหลัง เพราะผู้ใช้อาจกำลังอ่านอีกเรื่องอยู่
- **ทุกงานที่เรียก AI มี AbortController ของตัวเอง** ผ่าน `beginTask(name)` / `endTask(name, controller)`
  (`import`, `next`, `prefetch`, `batch`, `retranslate`)
- **เรียก AI ผ่าน `callLLM` / `callLLMJson` เท่านั้น** อย่า `fetch` ไปที่ API ของ AI ตรงๆ (ไม่งั้นจะไม่ถูกนับ token และไม่ผ่านเพดานค่าใช้จ่าย)
- **เพิ่มฟีเจอร์ใหม่ให้เพิ่มคำอธิบายใน `APP_HELP` (js/assistant.js)** ไม่งั้นผู้ช่วย AI จะตอบเรื่องฟีเจอร์นั้นไม่ได้
- **แทนคำแปลของตอนผ่าน `applyTranslationToChapter(..., { reason })` เท่านั้น** จะได้เก็บฉบับเดิมในประวัติเวอร์ชันอัตโนมัติ (ที่อื่นที่เขียนทับ `chapter.paragraphs` ต้องเรียก `saveChapterVersion` เอง)
- **แสดง/อ้างอิงเลขตอนด้วย `computeChapterNumbers()`** (js/api.js) ไม่ใช้ลำดับใน array เพราะผู้ใช้อาจเริ่มอ่านจากกลางเรื่อง
- **ส่วนคำสั่งที่ไม่เปลี่ยนให้ส่งเป็น `system`** (เช่น `buildTranslationSystemPrompt`) เพื่อให้ผู้ให้บริการ cache ได้ ห้ามใส่เนื้อหาหรือคลังศัพท์ที่เปลี่ยนทุกครั้งลงใน system
- **อ่าน API Key ผ่าน `getSecret` / `setSecret`** ไม่ใช้ `localStorage` ตรงๆ (รองรับโหมดไม่จำ key)
- **ปลายทางใหม่ต้องเพิ่มใน `js/csp.js`** ไม่งั้นเบราว์เซอร์จะบล็อก
- ส่งย่อหน้าให้ AI แบบมีหมายเลข `{i, src}` และรับกลับเฉพาะ `{i, th}` แล้วนำ `src` จากต้นฉบับมาจับคู่เอง

## รันบนเครื่อง

แอพต้องเปิดผ่าน HTTP (เปิดไฟล์ `index.html` ตรงๆ จะใช้ไม่ได้ เพราะเบราว์เซอร์ไม่โหลดสคริปต์จาก `file://`)

```bash
python -m http.server 8765
```

แล้วเปิด http://localhost:8765 และหน้า unit test อยู่ที่ http://localhost:8765/tests/

## Deploy

GitHub Actions (`.github/workflows/pages.yml`) ทำ 2 ขั้นเมื่อ push เข้า branch `codex/complete-app`:
1. **test**: `node --check` ทุกไฟล์ใน `js/` แล้วรัน `tests/run-ci.mjs` (unit test ทั้งหมดใน Chromium + เปิดแอพจริง เปิดหน้าต่างหลัก ต้องไม่มี JavaScript error ปิดอินเทอร์เน็ตระหว่างทดสอบ)
2. **deploy**: ไป GitHub Pages เฉพาะเมื่อ test ผ่าน (pull request รันแค่ test)
ถ้าเปลี่ยนไปใช้ `main` ให้แก้ `on.push.branches` ใน workflow ด้วย

เมื่อแก้ไฟล์ของแอพแล้ว ควรเปลี่ยน `CACHE_NAME` ใน `sw.js` ทุกครั้งที่ออกเวอร์ชันใหม่
(ตอนออนไลน์แอพจะดึงไฟล์ล่าสุดก่อนอยู่แล้ว แต่การเปลี่ยนชื่อ cache จะช่วยล้างไฟล์เก่าที่ค้างอยู่)

## ข้อควรรู้

- API Key เก็บใน `localStorage` ของเบราว์เซอร์ (หรือ `sessionStorage` ถ้าเลือกไม่จำ key) และถูกส่งตรงไปยังผู้ให้บริการ AI เท่านั้น
- GitHub Pages ของบัญชีเดียวกันใช้ origin เดียวกัน (`<user>.github.io`) หน้าเว็บอื่นใน Pages ของบัญชีนี้จึงอ่าน API Key ได้ แนะนำให้ใช้ custom domain แยกสำหรับแอพนี้
- ยอด token/เงินในแดชบอร์ดเป็นยอดที่นับในเบราว์เซอร์นี้ ยอดที่ถูกเรียกเก็บจริงดูที่หน้าเว็บผู้ให้บริการ
- ข้อมูลทั้งหมดอยู่ในเบราว์เซอร์เครื่องเดียว หากล้างข้อมูลเว็บจะหายหมด ควรกด "สำรองข้อมูลทั้งหมด" ที่ชั้นหนังสือเป็นระยะ
- OpenAI-compatible provider ต้องอนุญาต CORS จากเบราว์เซอร์ (บางเจ้าไม่อนุญาต)
