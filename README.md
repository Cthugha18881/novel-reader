# NovelTranslate AI

เว็บแอพอ่านนิยายจีนแปลไทยด้วย AI ทำงานในเบราว์เซอร์ล้วนๆ ไม่มี backend และไม่ต้อง build
ข้อมูลนิยาย ตอน และคลังศัพท์ทั้งหมดเก็บใน IndexedDB ของเบราว์เซอร์เครื่องนั้น

## ความสามารถหลัก

- **วางลิงก์แล้วแปล**: ดึงเนื้อหาผ่าน `r.jina.ai` รองรับบทที่แบ่งหลายหน้า หาลิงก์ตอนถัดไปได้หลายภาษา (下一章 / 次へ / 다음화 / Next Chapter / ตอนต่อไป) และ `rel="next"`
- **หลายภาษาต้นฉบับ**: จีน ญี่ปุ่น เกาหลี อังกฤษ (ตรวจอัตโนมัติ แก้เองได้ต่อเรื่อง) prompt กฎตรวจ และคลังศัพท์ปรับตามภาษา
- **เว็บต้นฉบับ**: โปรไฟล์เว็บ (CSS selector) พร้อมเครื่องมือทดสอบ, Jina API key, ให้ AI ช่วยแยกเนื้อหาเมื่อเว็บดึงยาก, โหมดสารบัญ (หาตอนถัดไปแม่นยำ เรียงตอน เติมตอนที่ขาด)
- **วางข้อความ / ไฟล์ .txt .epub**: แยกตอนอัตโนมัติ เดา encoding ไฟล์จีน (GBK/Big5) และเข้าคิว "รอแปล"
- **เลือก AI ได้ 3 แบบ**: Google Gemini, Anthropic Claude, OpenAI / OpenAI-compatible (OpenRouter, DeepSeek, LM Studio ฯลฯ) ใส่ได้หลายคีย์ และหมุนคีย์อัตโนมัติเมื่อโควต้าเต็ม
- **คลังศัพท์อัจฉริยะ**: สกัดชื่อเฉพาะอัตโนมัติ, ล็อกคำแปล, ไฮไลต์ในเนื้อเรื่อง, แยกหมวด 7 หมวด, ใช้ร่วมทุกเรื่องหรือเฉพาะเรื่อง และตั้ง **คำแปลเฉพาะเรื่อง** ได้ (คำจีนเดียวกันแต่ละเรื่องแปลต่างกัน)
- **อ่านต่อเนื่อง**: infinite scroll, แปลบทถัดไปล่วงหน้า, แปลล่วงหน้าหลายบท (batch), จำตำแหน่งอ่านถึงระดับย่อหน้า
- **ส่งออก/สำรอง**: ส่งออกทั้งเรื่องเป็น TXT / EPUB, สำรองและนำเข้าข้อมูลทั้งหมดเป็น `.json` (ไม่รวม API Key)
- **PWA**: ติดตั้งเป็นแอพบนมือถือ/คอม และเปิดอ่านตอนที่บันทึกไว้ได้แม้ออฟไลน์

## โครงสร้างโค้ด

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` / `styles.css` | UI ทั้งหมด (modal ต่างๆ อยู่ในหน้าเดียว) |
| `js/db.js` | IndexedDB (`books`, `chapters`, `glossaries`), แคชคลังศัพท์, สำรอง/นำเข้าข้อมูล |
| `js/llm.js` | ชั้นเชื่อมต่อ AI: `callLLM()` / `callLLMJson()` รองรับ 3 provider, retry, หมุนคีย์, structured output (JSON schema), ยกเลิกงาน (`beginTask` / `abortTask`) |
| `js/lang.js` | ข้อมูลตามภาษาต้นฉบับ: ตรวจภาษา, คำแนะนำการแปล, ตัวอักษรที่ห้ามหลงเหลือ, เกณฑ์ความยาว |
| `js/api.js` | scraper (`scrapePage`), แยกประเภทเนื้อหา, prompt, pipeline แปล (`translateChapter`): แบ่งส่วน, ตรวจทาน, เกลา + ตรวจความหมาย |
| `js/source.js` | โปรไฟล์เว็บ + แยกเนื้อหาจาก HTML, AI ช่วยแยกเนื้อหา, สารบัญ, นำเข้าข้อความ/ไฟล์ (.txt/.epub) |
| `js/cleanup.js` | ทำความสะอาดคำแปลแบบไม่ใช้ AI (เครื่องหมาย, คำสะกดผิด, กฎแทนคำ) โดยไม่แตะคำในคลังศัพท์ |
| `js/bible.js` | คู่มือเรื่อง (ตัวละคร/สรรพนาม/แนวทางสำนวน), ตัวอย่างสำนวนจากที่ผู้ใช้แก้ |
| `js/glossary.js` | UI และ logic คลังศัพท์, คำแปลเฉพาะเรื่อง (override), ไฮไลต์คำ |
| `js/shelf.js` | ชั้นหนังสือ และระบบแปลล่วงหน้าหลายบท |
| `js/export.js` | ส่งออก TXT / EPUB (โหลด JSZip จาก cdnjs ตอนใช้งานครั้งแรก) |
| `js/app.js` | state ของหน้าอ่าน, การแสดงผล, import, ตั้งค่า, PWA |
| `sw.js` / `manifest.webmanifest` / `icons/` | PWA และ cache สำหรับออฟไลน์ |
| `tests/index.html` | unit test ของฟังก์ชันหลัก (เปิดในเบราว์เซอร์) |

### หลักการสำคัญในโค้ด

- **ฟังก์ชันแปลทุกตัวรับ `BookContext`** (`{ bookId, title, author, genre }`) เป็นพารามิเตอร์
  ห้ามอ่าน `currentBookId` / `currentBookGenre` ตรงๆ ในงานเบื้องหลัง เพราะผู้ใช้อาจกำลังอ่านอีกเรื่องอยู่
- **ทุกงานที่เรียก AI มี AbortController ของตัวเอง** ผ่าน `beginTask(name)` / `endTask(name, controller)`
  (`import`, `next`, `prefetch`, `batch`, `retranslate`)
- **เรียก AI ผ่าน `callLLM` / `callLLMJson` เท่านั้น** อย่า `fetch` ไปที่ API ของ AI ตรงๆ
- ส่งย่อหน้าให้ AI แบบมีหมายเลข `{i, src}` และรับกลับเฉพาะ `{i, th}` แล้วนำ `src` จากต้นฉบับมาจับคู่เอง

## รันบนเครื่อง

แอพต้องเปิดผ่าน HTTP (เปิดไฟล์ `index.html` ตรงๆ จะใช้ไม่ได้ เพราะเบราว์เซอร์ไม่โหลดสคริปต์จาก `file://`)

```bash
python -m http.server 8765
```

แล้วเปิด http://localhost:8765 และหน้า unit test อยู่ที่ http://localhost:8765/tests/

## Deploy

GitHub Actions (`.github/workflows/pages.yml`) จะ deploy ไป GitHub Pages อัตโนมัติเมื่อ push เข้า branch `codex/complete-app`
ถ้าเปลี่ยนไปใช้ `main` ให้แก้ `on.push.branches` ใน workflow ด้วย

เมื่อแก้ไฟล์ของแอพแล้ว ควรเปลี่ยน `CACHE_NAME` ใน `sw.js` ทุกครั้งที่ออกเวอร์ชันใหม่
(ตอนออนไลน์แอพจะดึงไฟล์ล่าสุดก่อนอยู่แล้ว แต่การเปลี่ยนชื่อ cache จะช่วยล้างไฟล์เก่าที่ค้างอยู่)

## ข้อควรรู้

- API Key เก็บใน `localStorage` ของเบราว์เซอร์ และถูกส่งตรงไปยังผู้ให้บริการ AI เท่านั้น
- ข้อมูลทั้งหมดอยู่ในเบราว์เซอร์เครื่องเดียว หากล้างข้อมูลเว็บจะหายหมด ควรกด "สำรองข้อมูลทั้งหมด" ที่ชั้นหนังสือเป็นระยะ
- OpenAI-compatible provider ต้องอนุญาต CORS จากเบราว์เซอร์ (บางเจ้าไม่อนุญาต)
