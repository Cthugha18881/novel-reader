# NovelTranslate AI — UX/UI Audit

ขอบเขต: แอพ v3.7.0 (เว็บ static, ข้อมูลในเครื่อง) · ไม่ต้องล็อกอิน · หน้าจอ 1280×800 และ 375×812 · ธีม ถนอมสายตา / สว่าง / มืด · 6 ต.ค. 2026
หน้าที่ตรวจ: หน้าอ่าน (ข้อมูลทดสอบ 3 ตอน), หัวแอพ/แถบล่าง, ตั้งค่า, ชั้นหนังสือ, คลังศัพท์, หน้าแรกของผู้ใช้ใหม่ (คู่มือเริ่มต้น)
วิธี: สคริปต์วัดจาก ux-ui-audit (probe-core / heuristics / perception / ltr / focus) + อ่านข้อความทุกหน้า + นับจากซอร์สโค้ด
มาตรฐานที่ใช้: WCAG 2.2 AA สำหรับ accessibility, Nielsen 10 heuristics สำหรับการใช้งาน (เป็นการให้เหตุผล ไม่ใช่ผ่าน/ไม่ผ่าน)
หมายเหตุการวัด: หน้าต่างเบราว์เซอร์ทดสอบถูกซ่อน CSS transition จึงไม่เดิน ต้องปิด transition ชั่วคราวก่อนวัดสีของธีม (ผลชุดแรกที่ไม่ได้ปิด ไม่นำมาใช้)

## Findings

### 01 · Critical · หน้าแรกของผู้ใช้ใหม่
**หน้าแรกที่ผู้ใช้ใหม่เห็นเป็นบันทึกของนักพัฒนา และมีกล่องเตือนข้อผิดพลาดสีแดง**
ผู้ใช้ที่เพิ่งเปิดแอพครั้งแรกไม่ได้รับคำแนะนำว่าต้องทำอะไร (ใส่ API Key → วางลิงก์) และเห็นคำเตือนที่ไม่เกี่ยวกับตัวเอง ทำให้ดูเหมือนแอพเสียตั้งแต่แรก
```
ยินดีต้อนรับสู่ NovelTranslate AI v3.7.0
ระบบได้ทำการแยกโครงสร้างโค้ดเป็น Modular Architecture เรียบร้อยแล้ว
⚠️ ไม่พบลิงก์ของตอนถัดไป
ตอนนี้อาจเป็นตอนล่าสุดของเว็บ ... 🔗 วาง URL ตอนถัดไป
```
แก้: แทนคู่มือเริ่มต้นด้วยหน้าต้อนรับที่มีขั้นตอนชัด (1 เลือก AI / ใส่คีย์ 2 วางลิงก์หรือไฟล์) ไม่แสดงแถบ "ไม่พบลิงก์ตอนถัดไป" กับหนังสือคู่มือ ซ่อนปุ่ม "แก้ไขชื่อเรื่อง/ชื่อตอน" ของหนังสือคู่มือ

### 02 · Critical · ทั้งแอพ
**ช่องกรอกทุกช่องไม่มีตัวบอกโฟกัสเลย และทั้งไฟล์ CSS ไม่มีสไตล์ :focus / :focus-visible**
ผู้ใช้คีย์บอร์ดมองไม่เห็นว่ากำลังพิมพ์ช่องไหน (WCAG 2.4.7)
```
styles.css:330  .form-input { ... outline: none; ... }
probe-heuristics → interactionStates.ruleCounts: focus 0, focusVisible 0
```
แก้: ลบ outline:none ใส่ :focus-visible ที่ทุกปุ่ม/ช่อง (วงแหวน 2px สีที่ต่างจากพื้นหลัง ≥ 3:1 ทุกธีม)

### 03 · Major · หน้าอ่าน (มือถือ)
**ปุ่ม "ตั้งค่า" อยู่นอกจอบนมือถือ ต้องปัดแถบหัวไปทางขวาถึงจะเจอ และไม่มีสัญญาณว่าปัดได้**
```
375px: button "ตั้งค่า" right = 406px (จอกว้าง 375)
```
แก้: จัดเมนูมือถือใหม่ ให้ปุ่มที่ใช้บ่อยอยู่แถบล่าง ที่เหลือรวมในเมนู "เพิ่มเติม"

### 04 · Major · หน้าอ่าน
**ย่อหน้าเปิดดูต้นฉบับ/แก้คำแปล/บุ๊กมาร์ก/ฟังจากตรงนี้ ได้ด้วยการแตะเท่านั้น**
ย่อหน้าเป็น div ที่มี onclick ไม่มี tabindex / role ผู้ใช้คีย์บอร์ดและโปรแกรมอ่านจอเข้าถึงฟีเจอร์รายย่อหน้าไม่ได้ทั้งหมด (WCAG 2.1.1)
```
document.querySelector('.para-th').tabIndex → -1
```
แก้: ทำย่อหน้าเป็นปุ่ม (role="button", tabindex="0", Enter/Space เปิด) หรือมีเมนูย่อหน้าที่เข้าถึงด้วยคีย์บอร์ด

### 05 · Major · ทั้งแอพ
**ใช้กล่องของเบราว์เซอร์ alert/confirm/prompt 164 จุด**
บล็อกทั้งหน้า ปิดด้วยปุ่มที่เขียนว่า "OK/Cancel" ซึ่งไม่บอกผลของการกด มือถือบางรุ่นบล็อกกล่องซ้ำ และหน้าตาไม่เข้ากับแอพ
```
alert( 119 · confirm( 38 · prompt( 7  (js/*.js)
ตัวอย่าง: "กด OK = เก็บย่อหน้าที่แก้ไว้ (แปลใหม่เฉพาะย่อหน้าอื่น) กด Cancel = แปลใหม่ทั้งหมด"
```
แก้: ทำคอมโพเนนต์กล่องยืนยันของแอพ (ปุ่มเขียนเป็นคำกริยาบอกผล เช่น "เก็บที่แก้ไว้" / "แปลใหม่ทั้งหมด") ข้อความแจ้งผลใช้ toast

### 06 · Major · หน้าอ่าน
**ปุ่ม 🔄 (แปลบทนี้ใหม่ ใช้โควตา AI) เป็นไอคอนลอย ขนาด 32×32 อยู่ติดปุ่มอื่น กดครั้งเดียวเริ่มแปลทันที**
กดพลาดแล้วเสียเงินจริง และบนมือถือปุ่มลอยทับบริเวณชื่อเรื่อง
แก้: ย้ายเข้าเมนูของตอน ยืนยันพร้อมบอกค่าใช้จ่ายโดยประมาณก่อนแปล

### 07 · Major · ทั้งแอพ
**หน้าต่าง (modal) 20 อันไม่มี role="dialog"/aria-modal ไม่ล็อกโฟกัส และกด Esc ปิดไม่ได้**
```
.modal-overlay = 20 · [role=dialog] ใน modal = 0 · โค้ดไม่มีตัวจัดการปุ่ม Escape
```
แก้: คอมโพเนนต์ modal กลาง (role, aria-modal, aria-labelledby, ล็อกโฟกัส, Esc ปิด, คืนโฟกัสเมื่อปิด)

### 08 · Major · ตั้งค่า
**หน้าตั้งค่าเป็นหน้ายาวหน้าเดียว รวมเรื่อง AI, การแปล, เว็บต้นฉบับ, ข้อมูล/สำรอง, การใช้งาน AI, เทียบโมเดล**
ต้องเลื่อนหาเอง ไม่มีหมวด (Nielsen #6 recognition rather than recall)
แก้: แบ่งหมวด (AI · การแปล · การอ่าน · ข้อมูลและความปลอดภัย · ขั้นสูง)

### 09 · Major · ทั้งแอพ
**ชื่อเรียกและภาษาไม่คงที่ ไทยปนอังกฤษ**
```
หัวแอพ "คลังศัพท์" · ชื่อหน้าต่าง "คลังคำศัพท์สากล (Smart Glossary Engine)"
ตัวเลือก "🌐 คำสากลเท่านั้น (Global)" "📦 คำทั้งหมดในคลัง (All Terms)"
"ชั้นหนังสือ" · ชื่อหน้าต่าง "ชั้นหนังสือของฉัน (ในเครื่อง)"
```
แก้: คำเรียกเดียวต่อ 1 สิ่ง ทำตารางคำศัพท์ของ UI (ใช้กับ APP_HELP ของผู้ช่วยด้วย)

### 10 · Accessibility · หน้าอ่าน/ชั้นหนังสือ/คลังศัพท์ · SC 1.4.3
**สีน้ำเงินแบรนด์ #2563eb ใช้เป็นสีตัวอักษรทุกธีม ตัวเล็กบนพื้นอ่อนและพื้นมืดไม่ถึง 4.5:1**
```
✎ แก้ไขชื่อเรื่อง (10px)  3.85:1 ถนอมสายตา · 4.31:1 สว่าง
🏷️ เซียนเซีย · จีน ✎      4.13:1 ถนอมสายตา · 4.41:1 สว่าง · 2.92:1 มืด
ชื่อในคลังศัพท์ (มืด)      3.35:1 บน rgb(22,27,34)
👤 บุคคล/สัตว์ (ป้ายหมวด)  4.22:1 ถนอมสายตา
```
แก้: แยก token สีตัวอักษรเน้น (accent-text) ตามธีม เช่น #1d4ed8 ในธีมสว่าง, #93c5fd ในธีมมืด

### 11 · Accessibility · ทั้งแอพ · SC 1.4.11
**วงแหวนโฟกัสของเบราว์เซอร์บนพื้นถนอมสายตา 2.04:1**
```
outline auto 1px rgb(229,151,0) บน rgb(244,236,216) → 2.04:1 (ต้อง ≥ 3:1)
```
แก้: พร้อมกับข้อ 02

### 12 · Accessibility · ทั้งแอพ · SC 1.4.4
**viewport ปิดการซูม ผู้ใช้สายตาไม่ดีขยายด้วยนิ้วไม่ได้**
```
<meta name="viewport" content="... maximum-scale=1.0, user-scalable=no">
```
แก้: เอา maximum-scale / user-scalable ออก

### 13 · Accessibility · หน้าอ่าน · SC 3.1.2
**ต้นฉบับภาษาจีนไม่มี lang จึงรับ lang="th" ของหน้าไป และแสดงด้วยฟอนต์ monospace**
โปรแกรมอ่านจออ่านจีนด้วยเสียงไทย และฟอนต์ที่เลือกอักษรจีนผิดชุดได้
```
.para-src-text: ownLang null · inherited "th" · font-family monospace
```
แก้: ใส่ lang ตามภาษาต้นฉบับของเรื่อง (zh / ja / ko / en) ใช้ฟอนต์ที่รองรับ CJK

### 14 · Accessibility · ตั้งค่า/คลังศัพท์/ชั้นหนังสือ · SC 4.1.2 / 3.3.2
**ช่องกรอกไม่มีชื่อที่โปรแกรมอ่านจออ่านได้**
```
textarea#llm-keys-area · input#llm-model-input · input#retry-limit
input#gloss-search-input · input#gloss-src · input#gloss-tgt · input.gloss-item-chk
input#batch-input-<bookId>
```
แก้: ผูก label for= กับทุกช่อง (label ที่มองเห็นมีอยู่แล้วบางช่อง แค่ไม่ได้ผูก)

### 15 · Accessibility · ปุ่มไอคอน · SC 2.5.3 / 4.1.2
**ปุ่มที่มีแต่อีโมจิ (🔎 🎧 🔄 🔍+ ⛶ 💬) ชื่อที่อ่านออกเสียงคือชื่ออีโมจิ ไม่ใช่การทำงาน**
title มีอยู่ แต่ชื่อของปุ่มคำนวณจากเนื้อหาก่อน title จึงไม่ถูกใช้
แก้: aria-label ภาษาไทยทุกปุ่มไอคอน + tooltip ที่มองเห็น

### 16 · Accessibility · ชั้นหนังสือ/คลังศัพท์ · SC 2.5.8
**ปุ่มเล็กกว่า 24 px**
```
ชั้นหนังสือ: ✕ ปิด 15×24 · "ลบทั้งเรื่อง" 62×23 · "⚡ เริ่มแปลล่วงหน้า" 106×21 (ปุ่มเล็ก 9 ปุ่ม)
คลังศัพท์: 🔄 ✎ ✕ ต่อคำ (เล็กกว่า 24 px)
```
แก้: ปุ่มเล็กสุด 32 px บนมือถือ 44 px สำหรับปุ่มหลัก

### 17 · Accessibility · ทั้งแอพ · SC 4.1.3
**ข้อความสถานะ (toast, ความคืบหน้าการแปล) ไม่ประกาศให้โปรแกรมอ่านจอ**
```
[aria-live] = 0
```
แก้: aria-live="polite" ที่ toast และแถบความคืบหน้า

### 18 · Note · หน้าอ่าน
**หน้าแรกบนจอมีปุ่มให้กด 28 ปุ่ม (คอม) / 23 ปุ่ม (มือถือ)** หน้าอ่านควรเด่นที่เนื้อเรื่อง
```
Hick index 4.86 (คอม) / 4.58 (มือถือ) · ช่วงทั่วไป 3.2–4.0
```
แก้: ซ่อนเครื่องมือที่ไม่ใช้ระหว่างอ่านไว้ในเมนู

### 19 · Note · ทั้งแอพ
**สไตล์เขียนใน HTML/JS โดยตรง 546 จุด (index.html 310, js 236) ใช้ CSS variable แค่ 4 ตัว**
ทำให้แต่ละหน้าต่างหน้าตาต่างกันเล็กน้อยและแก้ทั้งแอพยาก (สาเหตุของข้อ 10)
แก้: ระบบ token + คลาสคอมโพเนนต์ แล้วทยอยย้ายสไตล์ inline

### 20 · Note · หน้าอ่าน
**ตัวอักษรเล็กกว่า 12 px บนหน้าอ่าน** "✎ แก้ไขชื่อเรื่อง" 10px · "✎ แก้ไขชื่อตอน" 10px · ".TXT" 11px

### 21 · Note · ทั้งแอพ
**รอโหลดใช้ spinner อย่างเดียว** ส่วนที่รอนาน (แปลตอน 20–60 วินาที) ควรบอกขั้นตอนที่ทำอยู่ (มีบางส่วนแล้ว) และพื้นที่ที่ผลจะมาแสดง

## สิ่งที่ดีอยู่แล้ว
- ไม่มีหน้าที่เลื่อนข้างทั้งที่ 375 และ 1280 px (layout.horizontalOverflow = null)
- ตัวอักษร 8 ขนาด, น้ำหนัก 3 แบบ, มุมโค้ง 5 แบบ, สีตัวอักษร 3 สีบนหน้าอ่าน = ระบบไม่บาน
- ไม่มี long task เกิน 50 ms ระหว่างใช้งาน
- ปุ่มบนหน้าอ่าน 15/15 (มือถือ) สูง ≥ 24 px
- ธีมมืด หน้าอ่านและหน้าตั้งค่า ไม่มีจุดที่ความต่างสีไม่ผ่าน
- หัวเรื่องมี h1 เดียว, มี landmark main/nav/header ครบ, html lang="th"

## Where to start (ผลต่อความยาก)
1. ข้อ 12 viewport ซูม (1 บรรทัด)
2. ข้อ 02 + 11 วงแหวนโฟกัสทั้งแอพ (CSS ไม่กี่บรรทัด)
3. ข้อ 01 หน้าต้อนรับผู้ใช้ใหม่
4. ข้อ 10 token สีตัวอักษรเน้นตามธีม
5. ข้อ 14 + 15 ชื่อช่องกรอก/ปุ่มไอคอน
6. ข้อ 13 lang ของต้นฉบับ
7. ข้อ 07 คอมโพเนนต์ modal กลาง (แก้ทุกหน้าต่างพร้อมกัน)
8. ข้อ 05 กล่องยืนยันของแอพแทน alert/confirm
9. ข้อ 03 + 18 + 06 จัดเมนูหน้าอ่านใหม่ (ส่วนของการออกแบบใหม่)
10. ข้อ 08 แบ่งหมวดตั้งค่า, ข้อ 09 คำเรียกเดียวกันทั้งแอพ, ข้อ 04 ย่อหน้าใช้คีย์บอร์ดได้
11. ข้อ 19 ย้ายสไตล์ inline เข้าระบบ token (ทยอยทำพร้อมแต่ละหน้า)
